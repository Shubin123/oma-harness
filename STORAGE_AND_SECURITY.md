# Harness storage

The browser owns project data in the `oma-harness` IndexedDB database: conversations, message delivery receipts and states, drafts, workflows, outputs, tasks, tiers, and cleanup reports. Cache writes use IndexedDB transactions and revision checks. Snapshot decoding validates versions and project shapes; failed saves are surfaced to the user. Export provides a portable lossless JSON snapshot. Import validates records and keeps existing project IDs. Browser site data is specific to the browser profile and origin, so changing the server port uses a different cache.

Legacy server project files under `~/.oma/projects` remain readable for migration and CLI compatibility. Missing browser IDs can be imported without replacing cached records. Normal dashboard chat history is not written to those files. Server-side RALPH task memory is separate, under `.oma_memory`; it uses atomic snapshots and rejects malformed files instead of silently discarding them.

Credentials stay on the server. `~/.oma/credentials.json` is restricted to the owner where supported. The existing machine-derived XOR credential format is reversible obfuscation, not protection against another process running as the same user. Its format remains readable for migration compatibility. Codex links save the auth file path and model, and read tokens fresh from the original local login file. Claude Code links save the executable path and model; Claude Code owns its login and refresh. Browser project exports never include managed OAuth tokens or pasted credential values.

Claude Code chat runs with tools and MCP configuration disabled, hooks disabled, one agentic turn, no automatic API retries, and no persisted CLI transcript. It receives the browser's conversation on stdin. Provider-reported token totals are recorded, including cache token usage. The harness reserves estimated input/output tokens before invoking Claude and limits connector call counts; provider overhead can make actual usage exceed the estimate for a single call. The allowance is per run/send, not a subscription-wide billing limit.

A browser reload can interrupt delivery after the provider has accepted a request. Partial output is preserved and the UI offers an explicit retry. A repeated request ID is deduplicated while its bounded server receipt remains available. Server restarts discard those receipts, so uncertain delivery cannot be guaranteed exactly once across restarts.

Offline test logs and status records are in `.build_cache`. Live tests are opt-in and record only provider, pass/fail state, safe error, model, and duration. They never print credentials or store live conversation bodies. Local source snapshots made during migrations are outside the repository and exclude `.env`, credentials, and runtime login files.
